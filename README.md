ALEXIS:
El commit nada más guarda los cambios en tu compu (local) y el push ya los sube al internet (github) para que el equipo los pueda ver.
Siempre hay que hacer pull antes de modificar para bajarte la versión más actual del código. Si no haces pull primero, puedes sobreescribir el trabajo del compañero y hacer un desastre al querer subir lo tuyo.
Trabajar en ramas sirve para que cada quien programe su parte por separado sin afectar el código que ya sirve (main). Ya cuando verificas que jala bien, lo unes.
El conflicto se ocasionó porque los dos cambiamos exactamente la misma línea de texto en el main al mismo tiempo, pero en diferentes ramas. Al querer juntarlo, github no sabía cuál título dejar.
Para solucionarlo, borramos el código empalmado y pusimos el título final que pedían las instrucciones de la práctica.
